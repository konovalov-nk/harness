Remote command execution with a live tmate view for the user.

# Tools

1. **rtmateRun** (primary): run a command over SSH and mirror it to tmate.
   - Args: `command`. Returns stdout/stderr.
   - Use for ~95% of tasks (install packages, read files, run scripts).
   - Fresh SSH session: it does NOT share sudo with the interactive window, so password-protected `sudo` FAILS. Use the sudo trick below.
2. **rtmateSend**: type into the live tmate session.
   - Args: `command`. Returns nothing.
   - ONE line per call. Never send multiple commands or paste a script.
   - Use for interactive prompts/TUIs, or for privileged commands in the user's authenticated session.
3. **rtmateRead**: capture the visible tmate screen.
   - Args: `lines` (optional). Returns the screen text.
   - For debug and verification only. Do NOT poll.

# Key workflows

- Interactive installer: start it with `rtmateSend`, stop immediately, ask the user to answer the prompts in the terminal, then verify the result with `rtmateRun`.
- Sudo trick:
  1. `rtmateSend(command="sudo apt update > /tmp/update.log 2>&1")`
  2. Wait for the user to enter the password.
  3. `rtmateRun(command="cat /tmp/update.log")`
- Complex content (scripts, Makefiles, JSON, heavy quoting): write the file locally in /tmp, copy it with `scp` through `rtmateRun`, then execute it remotely. Do not embed heredocs or multi-line code in `rtmateRun` unless it is truly a one-liner.

# Notes

- The session is pre-initialized; start running commands immediately.
- No polling loops with `rtmateRead`; trust the user to handle prompt timing.
